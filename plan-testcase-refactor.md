# Plan: Decouple Test Initial Conditions from the FLEKS Kernel

Companion to the code audit below (§1 lists every site that currently lives in the
kernel). Goal: **make adding a new test a zero-kernel-touching operation**, and remove
the silent-failure mode that has already bitten us once (the `HybridWave` vs
`hybridwave` case-sensitivity bug — see `tests/iaw-setup.md` / memory `17711739`).

## 0. Why this is worth doing (the structural problems)

1. **Closed enum + string chain → shotgun surgery.** Adding one test today edits 5
   files: `Constants.h.orig` (then regenerated by `Config.pl`), `Pic.h`, `Pic.cpp`,
   `Particles.h`, `Particles.cpp`.
2. **Silent failure.** The `#TESTCASE` if/else chain has *no* `else`. A misspelled name
   is a silent no-op — exactly what disabled the HybridWave test for the whole dev cycle.
3. **Ctor signature monotonic growth.** Every test appends a defaulted tail parameter to
   `Particles(...)`. C++ trailing-default continuity makes the signature brittle (a
   `SourceInterface` ctor already tripped on this once).
4. **Hot-loop pollution.** Three test branches in `add_particles_cell`'s innermost loop,
   a TopHat branch inside a `ParallelFor` lambda, a constant-velocity branch in the
   Boris mover — both a perf and a readability cost. Note `add_particles_cell` runs at
   *runtime* too (source injection), not just init.
5. **Cross-cutting side-effects hidden in unrelated code.** `nPartPerCell = 0` (in param
   parsing), `uMax = 1.0` (in time-step control), limiter short-circuit (in flux
   reconstruction) are *solver-behaviour overrides*, not initial conditions, yet are
   triggered implicitly by a test-case name.
6. **Non-parameterizable, non-composable.** `fill_convection_wave()` is literally
   `fill_hybrid_wave(0.2)` — yet it cost an enum value + a method + a dispatch line.
   Only one test case can be active at a time.
7. **Dead code.** `Pickup` has zero references anywhere; `moveParticlesWithConstantVelocity`
   is never assigned (always false) yet occupies two hot-loop branches.

## 1. Design: Initial-Condition plugin + self-registering factory

**Invert the dependency:** the kernel doesn't know about tests; tests know about the
kernel. The kernel exposes a *narrow facade* (`PicICFields`) — not a `friend Pic`.

### 1.1 Layout & build

```
include/InitialCondition.h      # abstract base + registry + PicICFields facade
src/InitialCondition.cpp        # registry implementation (+ case-normalizing lookup)
src/ic/LightWaveIC.cpp
src/ic/HybridWaveIC.cpp         # parameterized; also covers ConvectionWave
src/ic/IonAcousticWaveIC.cpp
src/ic/BeamIC.cpp
src/ic/TopHatIC.cpp
src/ic/RegisterAll.cpp          # one line per test
```

Add `src/ic/*.cpp` to `SRCS` in `src/Makefile`.

> **Build trap (important).** FLEKS builds a *static* archive `libFLEKS.a` (then
> `libPC.a` under SWMF). Pure static-object self-registration gets dropped by the linker
> (no symbol referenced ⇒ the `.o` is not pulled in). So we use an **explicit**
> `register_all_initial_conditions()` called once from `Domain::init` — *not*
> `--whole-archive`. This is still "one central list", but it is *owned by the test
> module* (one line per test), not the 5-file scatter we have today.

### 1.2 Interface

```cpp
class InitialCondition {
public:
  virtual ~InitialCondition() = default;
  virtual std::string name() const = 0;

  // Read own params (called right after #TESTCASE selects this IC).
  virtual void read_param(ReadParam& param) {}

  // Global config that must be fixed before child objects are built.
  // Replaces the inline `pInfo.nPartPerCell = 0` side-effect.
  virtual void post_process_param(PicSetup& setup) {}

  // --- field hook, after fill_E_B_fields ---
  virtual void set_fields(PicICFields& f) {}

  // --- particle hook ---
  virtual bool modifies_particles() const { return false; }  // hoist-out switch
  virtual void modify_particle(ParticleICState& s) const {}
  virtual void post_fill_particles(PicICFields& f) {}        // after fill, before sum_moments

  // --- solver-behaviour overrides (transitional; see §4) ---
  virtual bool override_umax(amrex::Real& uMax) const { return false; }
  virtual bool bypass_limiter() const { return false; }
};
```

Per-particle payload (covers exactly the Beam + IAW needs):

```cpp
struct ParticleICState {
  int speciesID, iParticleInCell, nPerCell, iLev;
  amrex::RealVect x;
  const amrex::Geometry* geom;
  amrex::Real q, uBulk, vBulk, wBulk;   // in/out
};
```

`set_fields` / `post_fill_particles` reach the kernel only through the narrow
`PicICFields` facade (`n_lev()`, `geom(iLev)`, `node_E`, `node_B`, `center_B`,
`fill_boundary_E_B()`, `kinetic_species()`, `species(i)`) — the facade is the point of
the decoupling.

### 1.3 Parameter parsing collapse

```cpp
} else if (command == "#TESTCASE") {
  std::string name;
  param.read_var("testCase", name);
  ic = ICRegistry::instance().create(name);     // unknown -> amrex::Abort + list all registered
  if (ic) ic->read_param(param);
}
```

This **independently kills problem #2**: the registry normalizes case and aborts on an
unknown name with the full registered list. Kernel members `testCase + beam + iaw`
(in both `Pic` and `Particles`) collapse to a single `std::unique_ptr<InitialCondition> ic`;
the `Particles` ctor tail becomes `const InitialCondition* ic = nullptr` — *one* param,
never growing.

### 1.4 Backward-compatible parameterization

`ConvectionWave` needs no PARAM.in change — register the same class twice with
different defaults:

```cpp
reg.add("HybridWave",     []{ return std::make_unique<HybridWaveIC>(0.02, /*perturbVel=*/true); });
reg.add("ConvectionWave", []{ return std::make_unique<HybridWaveIC>(0.20, /*perturbVel=*/false); });
```

`fill_convection_wave()`, one enum value, and one dispatch line all disappear at once.

### 1.5 Hot-loop cost

Hoist `const bool hasPartIC = ic && ic->modifies_particles();` *out* of the triple loop in
`add_particles_cell`; the inner loop keeps only one predictable branch + a virtual call
when hit. This is *cheaper* than today, where the inner loop unconditionally evaluates
`testCase == IonAcousticWave && iaw.pert != 0` and `testCase == Beam && speciesID == beam.iSpecies`.

## 2. TopHat is special — it is NOT an initial condition

TopHat's `uMax = 1.0` (time-step control) and `get_face` limiter short-circuit are
**solver-behaviour overrides**, not ICs. Correct fix: promote them to ordinary PARAM
options (cf. the existing `#CMAXE`), and the kernel learns *nothing* about the string
"TopHat":

- a fixed-`uMax` option (alongside `#CMAXE`);
- a limiter-toggle command at the level of `#LAGGEDLIMITER`.

`tests/tophat/PARAM.in` then uses generic options. The `override_umax` / `bypass_limiter`
hooks in §1.2 are kept **only as a transitional fallback** and removed in Phase 4.

## 3. Further: the wave family needs no C++ at all

4 of the 6 test cases (LightWave / HybridWave / ConvectionWave / IonAcousticWave) are the
*same operation* — a sinusoidal perturbation — differing only in which quantity is
perturbed (E / B / particle weight / particle velocity), amplitude, wavenumber,
polarization. Target state: one parameterized `#WAVEIC` (field-select, amplitude,
waveMode, polarization, weight-vs-velocity) covers all four, so a *new wave test costs
zero C++*. The plugin interface is then only for genuinely custom ICs (TopHat, Beam).

## 4. Phased migration (each phase compiles + all 8 tests pass)

| Phase | Contents | Risk |
|---|---|---|
| **0** | Delete `Pickup`; delete `moveParticlesWithConstantVelocity`; `#TESTCASE` unknown-name → `amrex::Abort` + case normalization | very low, merge first |
| **1** | Add `InitialCondition` + registry + `PicICFields`; migrate **only LightWave**. Kernel keeps `testCase` in parallel for now | low |
| **2** | Migrate HybridWave/ConvectionWave (`set_fields` + `post_fill_particles`), IAW/Beam (per-particle hook), TopHat | medium — preserve Beam `icount` semantics exactly |
| **3** | Delete `enum TestCase`, `BeamInfo`, `IawInfo`, ctor tail params, the 4 `fill_*` methods in `Pic`; keep `add_velocity_perturbation` but rename to a generic tool (its doc is hardcoded to HybridWave) | medium |
| **4** | Promote TopHat's `uMax` / limiter into ordinary PARAM commands; delete `override_umax` / `bypass_limiter` | medium |
| **5** | Unify the wave family under `#WAVEIC`; update `PARAM.XML` and the "how to add a test" section of `tests/AGENT.md` | low |

## 5. Two implementation details to watch

1. **`#TESTCASE` is parsed twice.** `Domain.cpp:941` lists it as a grid command, so
   `prepare_grid_info` runs `read_param(true)` once, then `roll_back` + full run. IC
   creation + `read_param` must be **idempotent**. It was likely added to the grid list
   precisely so the `pInfo.nPartPerCell = 0` side-effect took effect early; once that
   moves to `post_process_param(setup)`, the dependency becomes explicit and we can
   re-evaluate whether `#TESTCASE` still belongs in the grid list.
2. **`Constants.h` is generated from `Constants.h.orig` by `Config.pl`.** Removing the
   enum must edit `Constants.h.orig` (editing `Constants.h` directly is overwritten).

## 7. Acceptance (same bar as the Ohm plan)

- All 8 standalone `make EXE` functional tests pass after every phase.
- A deliberately misspelled `#TESTCASE` (e.g. `hybridwave`) aborts with the registered
  list — regression test for the bug class.
- `tests/tophat/PARAM.in` contains no `TopHat` string in the kernel path (verified by
  grep: `testCase == TopHat` and `bypass_limiter` gone from `src/`).
- `add_particles_cell` innermost loop has one hoisted `hasPartIC` branch (no per-particle
  `enum`/`struct` comparisons).
- `git grep -n "TestCase\|BeamInfo\|IawInfo"` returns only `src/ic/RegisterAll.cpp` and
  legacy test PARAM.in files.
